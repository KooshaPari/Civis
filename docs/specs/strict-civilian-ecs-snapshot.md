# Strict civilian ECS snapshot primitive

This opt-in primitive captures a bounded subset of current ECS entity state without touching the existing save API. It accepts only supported civilian component types, refuses unsupported components, external entity alignment, oversized entity indexes, and malformed or duplicate identities. It constructs a new isolated world after validation; a failed capture or restore does not alter the source world.

Its contract is current component and entity identity only. Faction identifiers are not resolved against a faction registry, and `OtherEntity` alignments are rejected. It does not preserve the hecs allocator free list, future entity allocation, non-ECS simulation state, queued work, RNG, scene generation, or references held elsewhere. It must not be described as a complete simulation save or wired to `save.slot` as such. JSON input and output are capped at 16 MiB; decoding requires the exact canonical bytes emitted by `to_json`, rejects duplicate keys and unknown nested fields, and DNA is capped at 64 KiB. The API cannot recover allocator history or validate faction identity. A seed-42 default simulation contains non-civilian entities and is rejected; it is not an acceptance witness for the normal game.

The experimental extension recognizes optional cluster membership, psyche, social graph, and psyche-driven behavior components. Social ties are capped at the engine limit and must be strictly ordered by target ID; non-finite social and psyche values are rejected. Graph references are not validated against a restored registry; unsupported components still fail closed. Missing optional fields retain their previous canonical representation.

Compatibility is one-way: this reader accepts canonical v1 snapshots lacking these fields, but older strict v1 readers reject records containing them. Version negotiation or a new schema version is required before persisted or cross-version use.
